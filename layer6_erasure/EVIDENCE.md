# Layer 6 erasure: evidence on fresh seeds and at scale

MOCK stores generated by our own seeder (the organisers' real layout is not available). Fresh random seeds the agent was never developed on. 'completeness' = seeded copies removed; 'silent' = copies left behind that the agent did NOT flag for a human; 'collateral' = other borrowers' or decoy records deleted by mistake. Limit: 15 minutes (900 s) per erasure request.

## Notes added by hand (20 Nov)
- **Name-collision fix.** The first version of this table had 1 wrong deletion at 3,000 borrowers: erasing a borrower whose name was "A. Yadav" deleted another borrower's debug-log line `DEBUG payload name=Arjun A. Yadav ...`, because the vault's matcher treated "A. Yadav" as a full-name hit inside the longer name and the agent deletes unique name-only hits. The matcher now reports `name_embedded` when the full name is only part of a longer capitalised name (also when glued to markup such as `name=`), and the agent reports that record as ambiguous instead of deleting it. **Now: 0 wrong deletions at 3,000 borrowers and on every fresh seed; completeness and the number of PARTIAL requests are unchanged** (17 of 120). Limits: it needs capital letters, so Devanagari / Kannada / Tamil and all-lowercase text still match as a plain full name. Tests: `test_a_name_inside_a_longer_name_is_not_a_full_name_match_but_is_still_reported`, `test_another_borrowers_longer_name_is_not_deleted_and_the_request_is_partial`.
- **Timings in this run were taken while other jobs ran** (a browser rehearsal, test suites), so they are an upper bound: an earlier run on a quieter machine measured 11.7 s for the slowest request at 56,013 records (the matcher itself is no slower: 6.0 us vs 5.9 us per text on 56,000 texts).
